任务做着做着，很容易忘记一个回答对应哪个分支、哪份文件、哪次构建。给 Agent 清晰的任务是一半，保留工作上下文是另一半。

## 给每件事一个位置

在 Ait 中，先添加项目，再围绕具体任务组织工作区。命名可以直接说明目标，例如“整理导航”“修复登录”或“更新文档”。

将相关 Agent 会话、文件与终端留在同一个工作区，让你随时知道当前任务正在修改什么。

## 请求里写明完成标准

比起“优化一下首页”，更有用的是具体说明范围与验证方式：

> 调整首页导航，让它在 390px 的手机屏幕上可用。保留现有品牌样式，检查菜单展开与关闭，并运行构建。

明确的完成标准帮助你判断结果，也让下一轮沟通更准确。

## 回到文件，而不只看总结

Agent 的总结提供线索，实际 Diff 说明发生了什么。检查修改范围，阅读关键文件，再运行与改动相关的验证。

构建通过以后，如果这是一个界面任务，还需要打开页面检查实际表现。命令输出与视觉验证回答不同的问题。

## 隔离并行任务

需要同时推进几件事时，使用 Git worktree 工作流，让不同任务有自己的目录和分支。它帮助管理修改冲突，但不是安全沙箱。

任务结束后，检查分支状态与变更，再决定如何合并。更多基础概念见 [工作区文档](/zh/docs/workspaces/)。

## 给下一次继续留好入口

完成一轮工作后，留下明确的下一步：哪些部分已检查、哪些仍有问题、下一次要验证什么。好的上下文让换一个 Agent、换一块屏幕或隔一天继续，都不必从头回忆。
