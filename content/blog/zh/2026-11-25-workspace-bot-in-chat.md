离开工位之后，其实很少有人想在手机屏幕上认真改几十行代码。更多时候只是突然想起一件具体的事：让 Agent 汇总一下这个分支本周改了什么、查一下某个报错是从哪次提交引入的，或者盯住刚提上去的 PR 看 CI 过了没有、评审人留了什么意见。

每次都专门切进开发工具再挑主机和会话，步骤有点绕；可如果直接把一个拥有完整终端权限的机器人挂到聊天群里，又不放心。Ait 的**工作区 Bot** 就是按这个场景设计的。

## 一个工作区一个 Bot，先在应用内试顺手

工作区 Bot 目前在测试功能里，开启路径是 **设置 → 关于 → 测试功能**。打开后，在任意工作区的 **新建** 菜单里选 **Bot**（如果工作主机上的 daemon 版本偏旧，按提示先升级）。

每个工作区可以单独配一个 Bot，选定它使用的 Provider、模型、允许的 Agent 模式和工具分组。不需要一开始就接外部聊天软件——Ait 内置了对话入口，你可以直接在里面丢几个小任务试试效果，顺便在 **任务** 标签里看它的执行记录和待回答问题。

试顺手之后，再按需要接外部聊天渠道。目前支持五个平台：

- **Telegram**：填 BotFather 的 Token，打开验证链接点 Start；群聊需要单独启用，按 `@` 提及或回复触发。
- **飞书 / Lark**：中国区飞书支持扫码或手动填凭据，国际版 Lark 使用独立应用凭据；群聊同样需要开启并 `@` 机器人。
- **微信**：扫码接入，只支持单聊；会话过期后重新扫码即可。
- **QQ**：支持扫码或手动配置，群聊单独开启，回复受 QQ 被动回复窗口限制。
- **iMessage**：通过 Photon 托管线路接入，只支持单聊。

从哪条对话发起的任务，完成、失败或需要补充信息时就会把结果回传到哪条对话；如果外部渠道临时停用或不可达，回报会自动退回到 Ait 内置对话，所有外部记录也都可以在 Bot 标签页里翻看。

需要注意一点：消息渠道现在不再使用旧版发送者名单做过滤。打算在群聊里启用之前，先在聊天平台那边确认好群成员范围和触发规则。

## 跟进 PR 和 MR：不用隔五分钟刷一次网页

如果工作主机上已经登录了 `gh` 或 `glab`，支持 PR 跟进的版本还能直接把同一仓库里的 GitHub PR 或 GitLab MR 交给 Bot 盯。

交办之后，任务详情里会持续汇总审核状态和 CI 检查进展，并按来源和权限处理评审意见。不想继续跟了，直接取消任务就行，不需要一直盯着浏览器标签页。

## 权限怎么收口，不至于失控

把聊天软件接到代码仓库，大家最担心的通常不是“能不能干活”，而是“会不会背着我乱跑命令”。工作区 Bot 的权限由三层一起决定：工作区范围、Provider 模式，以及你在 Bot 设置里勾选的工具分组。

两条默认规则很关键：

1. **脚本和终端工具分组默认关闭。** 如果你只是想在微信或飞书里查代码、理改动、跟进 PR，完全可以保持关闭；确实需要跑构建或测试命令时，再按任务需要放开。
2. **Bot 不会替你批准 Provider 的权限请求。** 一旦底层 Agent 需要申请高敏感权限，任务会停下来等你处理，你切回 Ait（比如[任务总览](/zh/docs/task-board/)）看清具体操作后再点同意或拒绝。

另外，暂停 Bot 只会停止接收新的外部消息，它已经派出去跑的 Agent 会话仍需你在工作区或任务总览里单独管理。

完整的渠道配置步骤和凭据说明可以看 [工作区 Bot 文档](/zh/docs/bots/)，以及主仓库的 [Bot 操作手册](https://github.com/ait-app/ait/blob/main/docs/operations/bots.md)。
