你在电脑上让 Agent 跑着一轮大改动，起身去倒杯水或者出门坐地铁，想在手机上看一眼进度、顺手批个权限。这时候手机上显然不可能重装一套 Rust 工具链和项目依赖。

Ait 的架构围绕这个很直接的前提设计：**运行环境留在工作主机，其他设备只做客户端。**

## 工作主机持有全部上下文

真正跑活的是主机上的 Rust daemon（桌面版内置，或独立安装的 `aitd`）以及本机装好的原生 Agent CLI。代码目录、Git 状态、工作区记录和终端会话都留在那台电脑或服务器上。

客户端（另一台桌面端、iOS、Android 或 Web）通过同一套协议连过去读取状态、发消息、看 Diff。连接手机不会把仓库复制到手机，也不会把 Agent 迁移到云端容器；只要工作主机在线，所有屏幕看到的都是同一份现场。

## 两种连接路径：在线服务和直接连接

不同网络环境需要不同连接方式，Ait 支持两条路：

- **在线服务（账户中继）**：工作主机和客户端登录同一 Ait 账户，主机主动出站接入在线服务，客户端从在线主机列表直接选中即可连接。不需要公网 IP，也不用折腾路由器端口转发。桌面、Android、iOS 和托管网页版 [Ait for Web](https://aitapp.cn/) 都支持这套方式；普通在线业务统一走 Hub，文件下载保留独立 Relay 通道。
- **直接连接**：不想走账户时，桌面和移动端可以在可信局域网或 VPN 内直连 daemon 监听地址与访问令牌，也可以让 daemon 只监听 `127.0.0.1:7316`，在本地开一条 SSH 端口转发隧道连过去。

各端的能力边界也很明确：手机只当客户端，不作为工作主机发布；Windows 桌面版目前同样是纯客户端，用来连 Linux 或 macOS 主机；托管网页版 `aitapp.cn` 只走在线服务，本地开发 Web 客户端才支持直连。

## 切后台、断线和重连时发生了什么

移动网络和锁屏会让连接随时中断，这里有几件容易误解的事值得摊开说：

- **断线不会杀掉主机上的任务。** Agent 跑在工作主机里，手机掉网或合上浏览器标签页，任务仍然继续。重新连上后先看一眼会话当前状态，免得误以为没发出去而重复提交。
- **移动端切后台有连接保留窗口。** 新版 Android 和 iOS 切到后台后，会尝试保留账户中继连接和正在进行的下载最多 2 分钟，期间切回来可以直接复用；超过窗口后暂停网络活动，回前台再重新校验并恢复连接（系统仍可能提前挂起应用）。
- **WebSocket 订阅绑定在物理连接上。** 连接断开后订阅会释放，重连时需要重新确认主机状态并恢复订阅，所以在实现上把连接身份、订阅生命周期和会话数据拆开管理。
- **退出客户端不会撤销主机授权。** 机器授权、节点续租和在线重连都由 daemon 自己维护。只有显式断开主机同步或执行 `aitd logout`，才会清除机器授权。
