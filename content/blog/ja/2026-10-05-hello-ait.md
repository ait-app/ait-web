Ait を作り始める前、私たちの画面はいつもこうなっていました。左に Claude Code と Codex を動かしているターミナルが 2 つ、真ん中に差分を読むためのエディタ、右にビルド用 Linux マシンへつないだ SSH ウィンドウ。並行して動かすタスクが 3 つ 4 つに増えると、「いま権限承認待ちで止まっているタブはどれだ」と探すだけで結構な手間になり、席を離れれば作業が終わったのか詰まっているのかすら分かりませんでした。

API を薄く包んだだけのチャット画面を増やしたいわけでも、ローカルのリポジトリを毎回クラウドのサンドボックスへ持ち上げたいわけでもありません。それで Ait を作りました。

## 手元のネイティブエージェントをそのまま使う

Ait は現在、作業ホストにインストールされた **Codex、Claude Code、OpenCode、DeepSeek Harness、Antigravity CLI、Pi、Oh My Pi、MiniMax Code** に対応しています。

ログイン情報、モデルの契約、`CLAUDE.md`、スキル、MCP の設定はすべて各 CLI のものをそのまま引き継ぎます。Ait 自体はモデルのサブスクリプションを販売しませんし、各プロバイダーとのデータ取り扱いを書き換えることもありません。タスクに合うツールを同じ画面で使い分けられ、CLI ごとの対応機能の違いは [エージェントのセットアップ](/ja/docs/providers/) にそのまま記載しています。

## 会話、コード、ターミナル、Git を並べて扱う

プロンプトを送って返答が来るのは作業の前半だけで、そのあと差分を見てテストを回し、コンフリクトを直して PR を出すところまで続きます。

Ait のワークスペースでは、会話、ファイルツリー、差分、ターミナル、Git 操作が同じ画面に収まります。1 つのリポジトリで並行作業をするときは通常の Worktree やサンドボックス Worktree を分けられ、ホストやタスクが増えたら**タスク一覧**で「対応待ち / 実行中 / 要確認 / 完了」をまとめて見渡せます。

## 自分のマシンで動かし、手元の画面からつなぐ

Ait のバックエンドは Rust で書かれた軽量なデーモンです。

- macOS と Linux のデスクトップ版は同梱デーモンを自動で起動します。ローカルだけで使うなら Ait アカウントの作成やサインインは不要です。
- デスクトップ環境のない Linux サーバーや常時稼働の Mac mini では、単体バイナリの `aitd` を動かせます。
- 同じアカウントでサインインすれば、デスクトップ（Windows クライアント含む）、iOS、Android、[Ait for Web](https://aitapp.cn/) から作業ホストへ接続できます。信頼できる LAN や SSH トンネル経由のアカウント不要な直接接続も選べます。

試してみたい方は [ダウンロード](/ja/download/) からお使いの環境向けパッケージを入手し、[クイックスタート](/ja/docs/quick-start/) に沿って最初のエージェントをつないでみてください。ソースコードや最近の変更は [GitHub](https://github.com/ait-app/ait) で公開しています。
