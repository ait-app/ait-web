工作区把一次工作的上下文放在一起。你可以在项目中组织任务，查看 Agent 会话、目录文件、终端与 Git 变更。

## 项目与工作区

**项目**对应你要工作的代码目录。**工作区**组织具体工作内容与会话。Agent 在选择的工作目录中执行，不会凭空获得一个独立代码副本。

先添加项目，再创建对应工作区。使用现有目录时，确认目录中包含正确的代码、项目配置和说明文件。

## 让 Agent 理解任务

新建 Agent 后，清晰描述期望结果、相关文件和验证方式。例如：

> 为这个项目添加响应式导航。沿用现有样式，检查手机布局，并运行项目当前的构建命令。

Agent 使用自己的原生配置。查看 [Agent 接入](/zh/docs/providers/)，了解项目指令、技能与工具配置如何加载。

## 查看与验证变更

1. 在会话中了解 Agent 的执行过程。
2. 打开文件和 Diff，检查修改内容与范围。
3. 在终端运行项目需要的构建或验证命令。
4. 根据结果补充说明，或者继续下一步 Git 操作。

主页的产品演示仅展示这一工作流，不会执行真实任务或修改你的文件。

## Git worktree

需要隔离并行任务时，可以使用项目提供的 Git worktree 工作流。Worktree 让同一个 Git 仓库有多个工作目录，每个目录使用自己的分支与文件状态。

使用前确认 Git 仓库状态与目标分支，完成后检查变更再合并。Worktree 是目录与分支隔离，不是操作系统安全沙箱。创建后的项目 setup 可能仍在后台运行，等依赖安装和初始化完成后再执行任务。

## 提交与拉取请求

工作区主按钮会根据实际 Git 与 PR 状态提示下一步，例如提交、创建 PR、推送或查看 PR。需要 GitHub/GitLab 操作时，工作主机上的 Git 和对应 `gh` / `glab` 也需要完成认证。

“查看 PR”只打开已有请求，不会代替推送。遇到冲突、分支分叉或落后时，先处理 Git 状态，再继续。合并后确认工作区没有活动 Agent 或未处理的审批，再决定是否归档。

## 定时任务

从工作区的新建菜单打开定时任务，选择现有 Agent 或每次新建 Agent，配置提示词、间隔或 Cron、时区与运行次数。任务固定属于该工作区；需要隔离目录时，先创建对应的 worktree 工作区。

任务在工作主机的 daemon 上执行，关闭客户端标签页不会停止在线 daemon 的调度。主机关机或 daemon 停止时不会执行；周期任务不会补跑所有错过的触发。暂停只阻止后续自动触发，当前运行需要单独取消。

## 从另一台设备继续

连接工作主机后，远程设备访问主机上的工作区。文件和运行时仍在主机上，远程连接不等于把项目复制到手机。

连接方式与平台差异见 [连接与数据](/zh/docs/connection/)。
