工作区把一次工作的上下文放在一起。你可以在项目中组织任务，查看 Agent 会话、目录文件、终端与 Git 变更。

## 项目与工作区

**项目**对应你要工作的代码目录。**工作区**组织具体工作内容与会话。Agent 在选择的工作目录中执行，不会凭空获得一个独立代码副本。

先添加项目，再创建对应工作区。使用现有目录时，确认目录中包含正确的代码、项目配置和说明文件。

## 让 Agent 理解任务

新建 Agent 后，清晰描述期望结果、相关文件和验证方式。例如：

> 为这个项目添加响应式导航。沿用现有样式，检查手机布局，并运行项目当前的构建命令。

Agent 使用自己的原生配置。查看 [Agent 接入](/zh/docs/providers/)，了解项目指令、技能与工具配置如何加载。

## 查看与验证变更

1. 在会话中了解 Agent 的执行过程。
2. 打开文件和 Diff，检查修改内容与范围。
3. 在终端运行项目需要的构建或验证命令。
4. 根据结果补充说明，或者继续下一步 Git 操作。

主页的产品演示仅展示这一工作流，不会执行真实任务或修改你的文件。

## Git worktree

- **本地目录**：直接在项目检出中工作，适合不需要并行分支的任务。
- **新建 Worktree**：为并行任务使用独立目录和分支。普通 Worktree 只隔离目录与 Git 状态。
- **沙箱 Worktree**：在支持的 macOS / Linux 主机上为 Agent 进程额外限制写入。目前支持 Claude Code、Codex、Pi、Oh My Pi、OpenCode 和 MiniMax Code。它不是完整的读取或网络隔离。Linux 依赖 `bubblewrap >= 0.8.0` 与非特权用户命名空间，详见[平台支持](/zh/docs/platforms/)。

创建 Worktree 后，项目初始化可能仍在后台运行。先确认分支，并等待初始化完成。

## 工作区记事本

支持此功能的客户端可在 **设置 → 关于 → 测试功能** 开启后打开工作区记事本。每个工作区共享一份保存在主机数据目录中的 Markdown，适合记录约定或交接内容，不会随 Git 提交。桌面和 Web 可编辑，Android 和 iOS 只显示预览。具备权限的 Agent 可通过 [Ait MCP](/zh/docs/agent-tools/) 读写。

## 内置浏览器

桌面端可从工作区打开内置浏览器。远程工作区的浏览器经该工作主机访问页面，也能打开主机上的 `localhost` 页面。参见[远程主机浏览器登录示例](/zh/blog/browser-login-on-host/)。

## 提交与拉取请求

工作区主按钮会根据实际 Git 与 PR 状态提示下一步，例如提交、创建 PR、推送或查看 PR。需要 GitHub/GitLab 操作时，工作主机上的 Git 和对应 `gh` / `glab` 也需要完成认证。

“查看 PR”只打开已有请求，不会代替推送。遇到冲突、分支分叉或落后时，先处理 Git 状态，再继续。合并后确认工作区没有活动 Agent 或未处理的审批，再决定是否归档。

新版分组 Git 面板和“变基到远端”操作需要 v0.2.26 客户端与兼容主机。归档入口位于工作区菜单。工作区重置仅适用于满足条件的托管 Worktree，确认前请核对分支及将被清除的文件。

## 定时任务

在工作区的新建菜单打开定时任务，选择已有 Agent 或每次新建 Agent。查看[定时任务指南](/zh/docs/automation/)，了解间隔、Cron、运行历史和会话保留。

## 从另一台设备继续

连接工作主机后，远程设备访问主机上的工作区。文件和运行时仍在主机上，远程连接不等于把项目复制到手机。

连接方式与平台差异见 [连接与数据](/zh/docs/connection/)。
