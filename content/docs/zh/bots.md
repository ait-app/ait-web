每个工作区可以设置一个 Bot。它可将任务交给工作区里的 Agent，并在完成、失败或需要你处理时回报。功能取决于客户端和主机版本。

## 设置与连接

1. 在 **设置 → 关于 → 测试功能** 打开启用开关，再从工作区的 **新建** 菜单选择 **Bot**。出现升级提示时，先更新工作主机的 daemon。
2. 选择 Provider、模型和运行选项。在 Bot 设置中确认允许使用的 Agent 模式及工具分组。
3. 先在 Ait 内置对话中试用。连接外部渠道时，在 Bot 设置添加渠道，按界面完成验证后确认已启用。
4. 在聊天中交办具体任务，例如整理这个工作区本周的改动。用 **任务** 标签查看进展和待回答的问题。

| 渠道 | 接入与支持范围 |
| --- | --- |
| Telegram | 使用 BotFather 的 Token，打开验证链接并点 Start。群聊需启用，按提及或回复规则触发。 |
| 飞书 / Lark | 中国区飞书可扫码或手动填写凭据；国际版 Lark 使用自己的应用凭据。群聊需启用并提及机器人。 |
| 微信 | 扫码接入，仅单聊。会话过期后重新扫码。 |
| QQ | 扫码或手动配置。群聊需启用，回复受 QQ 的被动回复窗口限制。 |
| iMessage | 通过 Photon 托管线路接入，仅单聊。 |

消息平台的旧发送者名单已不用于过滤。启用群聊前，请确认平台端的可见范围和触发规则。渠道需要各自的凭据。详细步骤见 [Bot 操作手册](https://github.com/ait-app/ait/blob/main/docs/operations/bots.md)。

## 进展、PR 与权限

工作产生的回报通常回到发起的对话。渠道停用或不可用时，回报回到 Ait 内置对话。外部对话历史可在 Bot 标签页查看。暂停 Bot 会停止接收新的对话，已交办的 Agent 仍需单独管理。

支持 PR 跟进的版本可跟进同一仓库的 GitHub PR 或 GitLab MR，需要工作主机上已登录的 `gh` 或 `glab`。Bot 在任务详情展示审核与检查进展，并按来源和权限处理评审意见。取消任务可停止跟进。

Bot 的工具分组、工作区范围和 Provider 模式共同决定能力。默认未开启脚本和终端分组，Bot 会话也不会代你批准 Provider 权限请求。使用命令或终端的权限会扩大实际可执行范围，请按任务需要配置。
