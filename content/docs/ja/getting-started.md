Ait は、複数のエージェントを管理するローカルファーストのツールです。エージェントは作業ホストで動作します。共通のインターフェースから、セッションの管理、ファイルやコード変更の確認、ターミナルでの結果の検証ができます。

複数のエージェントの利用、複数ホストの管理、デバイスをまたいだ作業の継続については、[Ait が選ばれる理由](/ja/docs/why-ait/)をご覧ください。試す準備ができたら、[クイックスタート](/ja/docs/quick-start/)に進んでください。

## デスクトップアプリをインストールする

[ダウンロードページ](/ja/download/)でプラットフォームを選びます。公式のデスクトップリリースでは、現在 **Apple Silicon macOS** と **Linux x86_64** 向けのインストーラーを提供しています。

[Ait の公式リリース](https://github.com/ait-app/ait/releases/latest)から適切なファイルをダウンロードしてください。macOS では DMG を開いて Ait をインストールし、起動します。Linux では、配布パッケージを展開して実行するか、AppImage を使用します。リリースには、ダウンロードしたファイルを検証するための `SHA256SUMS` が含まれています。

デスクトップパッケージには Rust 製のデーモンが含まれています。デスクトップアプリが自動的に起動するため、Ait サーバーを別途インストールする必要はありません。

## エージェントを用意する

Ait にモデルのサブスクリプションは含まれていません。始める前に、作業ホストに対応するエージェント CLI（Claude Code、Codex、OpenCode など）を 1 つ以上インストールし、サインインしてください。

これらのツールをすでにターミナルで使っている場合は、既存のサインイン情報をそのまま使えます。Ait は DeepSeek Harness と Antigravity CLI にも対応しています。利用できるモデルと権限は、作業用コンピューターにインストールされているバージョンによって異なります。セットアップ方法と各連携の違いは[エージェントのセットアップ](/ja/docs/providers/)をご覧ください。

## 最初のワークスペースを始める

1. Ait を開き、ローカルのサービスに接続します。
2. ディレクトリを選択して、既存のプロジェクトを追加します。
3. ワークスペースを作成し、利用可能なエージェントを選びます。
4. タスクを説明し、会話の中で進捗を確認します。
5. ファイルと差分を確認し、ターミナルでプロジェクトの検証コマンドを実行します。

プロジェクトの整理方法と Git worktree については、[ワークスペース](/ja/docs/workspaces/)をご覧ください。

## 別のデバイスを接続する

デスクトップ、Android、iOS は、同じアカウントでサインインし、アカウントリレーを通じて作業用コンピューターを選択できます。Web では、[aitapp.cn](https://aitapp.cn/) にサインインしてクライアントを開きます。コンピューターはスリープさせず、Ait のサービスとエージェントを利用できる状態にしておいてください。

- Android：Google Play のクローズドテストへのアクセスをリクエストしてから、[参加リンク](https://play.google.com/apps/testing/dev.ait.mobile)を開きます。
- iPhone / iPad：事前のメール申請なしで、[TestFlight の公開招待](https://testflight.apple.com/join/fjc7g46u)から参加できます。
- デスクトップ環境のない Linux / macOS：[スタンドアロンデーモン](/ja/docs/daemon/)をインストールして認可します。

Google Play の参加資格には Google アカウントが使われ、アプリ内のサインインには Ait アカウントが使われます。両者は用途が異なります。ストアの参加資格とインストール手順は[対応プラットフォーム](/ja/docs/platforms/)をご覧ください。

接続方法を選ぶには、[接続とデータ](/ja/docs/connection/)と[対応プラットフォーム](/ja/docs/platforms/)をお読みください。

## Ait に貢献する

ドキュメントの修正、問題の再現、コードの改善を行う場合は、まず[コントリビュート](/ja/docs/contributing/)で、リポジトリの役割、開発ルール、検証の範囲、プルリクエストの手順を確認してください。

ソースから実行するには、[ローカル開発](/ja/docs/development/)をお読みください。Node.js 24、バージョン固定の Rust ツールチェーン、CMake、システムのビルドツールを用意し、デスクトップ、Web、モバイルのいずれかを選びます。Web サイトのドキュメントは別リポジトリの `ait-web` にあります。ローカルでのプレビューについてもガイドで説明しています。
