Ait では、実行とアクセスを分離しています。作業ホストがデーモンとエージェントを実行し、クライアントはそのホストに接続してワークスペースや会話にアクセスします。リモートアクセスを利用するには、作業用コンピューターとそのサービスをオンラインに保ってください。

## 正しいアドレスを選ぶ

| 用途 | アドレス |
| --- | --- |
| Web サイト、ダウンロード、ドキュメント | [ait-app.com](https://ait-app.com/) |
| アカウントと Web アプリの入口 | [aitapp.cn](https://aitapp.cn/) |
| 既定のアカウント API | `https://aitapp.cn/api` |
| ローカル開発用デーモン | `127.0.0.1:7316` |

マーケティング用 Web サイトはアカウント API ではありません。`/hosts` 管理ページも API アドレスではありません。

## アカウント経由で接続する

デスクトップ、Android、iOS は、アプリに設定されたアカウントサービスのアドレスを使用します。現在の設定は **サービス設定** で確認できます。ホスト型の Web クライアントはサイトのルートで動作し、同一オリジンの `/api` を使用します。管理コンソールは `/dash` にあります。Web サイト `https://ait-app.com` は製品情報とドキュメントを提供するもので、アカウント API のアドレスではありません。

1. 作業用コンピューターで **オンラインサービス → サインイン / 登録** を開きます。ホスト型のサインインを完了して Ait に戻ります。
2. 作業ホストがオンラインサービスと同期されていることを確認します。同期を停止している場合は、ホストの接続設定で有効にしてください。
3. 別のデスクトップデバイス、Android、または iOS で、同じアカウントと同じサービスにサインインします。**オンラインサービス** または **ホストを追加** を開きます。
4. オンラインのホスト一覧から作業用コンピューターを選び、保存済みホストに追加します。

現在のクライアントは、アカウントのステータスチャネルを通じてホストのスナップショットと接続可否を受け取ります。一覧には現在のマシン自身は表示されません。スマートフォンはクライアントであり、作業ホストとしては公開されません。ホスト型のサインインには、デスクトップと Android ではシステムブラウザー、iOS ではシステムの認証ウィンドウを使用します。ブラウザーからアクセスする場合は、[aitapp.cn](https://aitapp.cn/) にサインインして Web クライアントを開いてください。アカウントリレーでは、デバイス同士が同じローカルネットワークにいる必要はなく、作業用コンピューターがポート転送された公開ポートを公開する必要もありません。

セルフホストのアカウントサービスを使う場合は、**サービス設定** に API のベースアドレスを入力します。空欄の場合は `https://aitapp.cn/api` が使われます。新しいクライアントは、`:8443` を使うものを含め、保存済みの旧公式アドレスを移行します。カスタムのサービスアドレスはそのまま維持されます。両方のデバイスで同じサービスとアカウントを使用してください。

## 直接接続

デスクトップとモバイルのクライアントは直接接続を利用できます。ローカル開発用の Web クライアントもこの方法を使用します。ホスト型の Web クライアントはオンラインサービス経由で接続します。直接接続には、ホストのアドレス、ポート、デーモンのアクセストークンが必要です。

ローカル開発用の既定のリスナーは `127.0.0.1:7316` です。このアドレスは該当するホスト上でのみ有効なため、別のデバイスからは到達可能なホストアドレスが必要です。リスナーとブラウザーの Origin の設定については、[サーバー設定](/ja/docs/configuration/)をご覧ください。

## 認証情報の分離

- **Ait 接続トークン**は、クライアントをデーモンに対して認証します。
- **エージェントサービスの認証情報**は、Codex、Claude Code、OpenCode などのネイティブプログラムが各サービスにアクセスするために保存します。
- **アカウントの認証情報**は、ネイティブクライアントではプラットフォームのセキュアストレージに保存されます。セキュアストレージを利用できない場合、再起動後に再度サインインが必要になることがあります。Web クライアントは、サインイン状態を保持するためにブラウザーのストレージを使用します。

ブラウザーは WebSocket にアップグレードする前に、有効期間の短い使い捨ての接続チケットを交換します。サービスの Bearer トークンが URL に含まれることはありません。

## データは作業ホストに残る

プロジェクトのファイルとエージェントのランタイムは作業ホストに残ります。デスクトップのサービスデータディレクトリの既定値は `~/.ait-server-desktop`、スタンドアロンデーモンの既定値は `~/.ait-server` です。

ローカルで実行されるからといって、モデルへのリクエストがネットワークの外に出ないわけではありません。エージェントは、それぞれの設定に従ってプロバイダーと通信します。リモートモデルを使用する場合は、プロバイダーのデータポリシーをご確認ください。リモートクライアントは、選択した接続方法を通じてファイルや会話を読み取ります。

## 切断と再接続

新しい Android と iOS のクライアントは、バックグラウンドに移行してから最大 2 分間、アカウントリレー接続と進行中のダウンロードの維持を試みます。この時間内に戻ると、正常な接続を再利用できます。この時間を過ぎるとアカウントのネットワーク通信は一時停止し、アプリに戻ったときに再検証されます。オペレーティングシステムによってアプリが一時停止されたり、ネットワークがそれより早く中断されたりすることがあり、バックグラウンド実行は保証されません。

スマートフォンが切断されても、作業用コンピューターで実行中のエージェントが移動したり、自動的にキャンセルされたりすることはありません。送信が完了したか不明なタスクを再送する前に、再接続してセッションを確認してください。

現在のソースでは、マシンの認証、ホストリースの更新、オンラインの再接続はデーモンが担当します。有効な認証情報を持つデーモンが動作し続けている間は、クライアントを終了してもマシンの認証は取り消されません。**終了後もデーモンを実行し続ける** を有効にすると、ローカルプロセスを維持できます。ホスト同期を明示的に切断すると、オンライン接続が閉じられ、マシンの認証も消去されます。再接続するには、もう一度認証してください。デスクトップのライフサイクルに依存せず常時稼働させたい場合は、[スタンドアロンデーモン](/ja/docs/daemon/)を使用してください。

現在のデスクトップ、Android、iOS、Web の各クライアントは、通常のオンライン操作に Hub を使用します。Hub が利用できない場合は、従来のビジネス用トランスポートにフォールバックせず、明示的にエラーになります。ファイルのダウンロードには、独立した Relay チャネルが引き続き使われます。クライアント、デーモン、アカウントサービスの互換性をあわせて確認してください。詳しくは [ADR-204](https://github.com/ait-app/ait/blob/main/docs/decisions/clients/adr-204-hub-only-online-business-transport.md) をご覧ください。

プロトコル、シャットダウン時の動作、データディレクトリについては、[デーモンマニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/daemon.md)をお読みください。
