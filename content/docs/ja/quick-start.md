Ait は、エージェントのセッション、ファイル、コードの変更、ターミナルを 1 つのワークスペースにまとめます。エージェントは作業用のコンピューターで動作します。Ait はローカルで使うことも、スマートフォンやブラウザーから接続して使うこともできます。以下からインストール方法を選んでください。

## 始める前に

**Apple Silicon の Mac または Linux x86_64 のコンピューター**を作業ホストとして用意し、プロジェクトのディレクトリと、インストールとサインインが済んだエージェント CLI を 1 つ以上ご用意ください。Ait は Codex、Claude Code、OpenCode、DeepSeek Harness、Antigravity CLI、Pi、Oh My Pi、MiniMax Code に対応しています。設定の詳細は[エージェントのセットアップ](/ja/docs/providers/)をご覧ください。Windows x64 のデスクトップアプリはリモートクライアントとして使い、エージェントは作業ホストにインストールします。

Ait は各エージェントのサインイン情報とモデル設定をそのまま利用します。モデルのサブスクリプションは含まれていません。エージェントは、タスクを実行するホストにインストールしてください。スマートフォンやブラウザーはそのホストに接続します。

## 1. Ait をインストールする

### デスクトップアプリ（推奨）

[Ait のダウンロードページ](/ja/download/)でインストーラーを選びます。

- **macOS Apple Silicon**：DMG を開き、Ait を「アプリケーション」にドラッグして起動します。ZIP も利用できます。
- **Arch Linux**：安定版をインストール（main からビルドする場合は `ait-git` を指定）

  ```sh
  paru -S ait-bin
  ```
- **Debian / Ubuntu**：.deb を入手して実行

  ```sh
  sudo apt install ./Ait-*-linux-amd64.deb
  ```

- **Fedora / RHEL**：.rpm を入手して実行

  ```sh
  sudo dnf install ./Ait-*-linux-x86_64.rpm
  ```

- **その他の Linux x86_64**：AppImage を実行するか、tar.gz を展開します。サンドボックス Worktree に必要な `bubblewrap >= 0.8.0` と非特権ユーザー名前空間については、[プラットフォーム対応](/ja/docs/platforms/#linux-x86_64)を参照してください。
- **Windows x64**：クライアントをインストールし、オンラインサービス、直接接続、リモート SSH のいずれかで作業ホストに接続します。

macOS や Linux で Ait を開くと、同梱デーモンが起動します。ローカルで使う場合は Ait アカウント不要です。続けてエージェントを接続します。

### サーバー / スタンドアロンデーモン

[スタンドアロンデーモンのガイド](/ja/docs/daemon/)に従って、ヘッドレスの Linux や常時稼働の Apple Silicon Mac に `aitd` をダウンロードし、検証してインストールします。エージェント CLI とプロジェクトを用意し、下記の[オンラインサービス](#オンラインサービスで接続する)か [LAN での直接接続](#lan-で直接接続する)を選んでください。

## 2. エージェントを接続する

1. 選んだエージェントを**作業ホストのターミナル**で起動します。サインイン済みで、単独でタスクを処理できることを確認してください。
2. Ait に戻り、セッションの作成時にそのエージェントを選びます。既存のネイティブなサインイン情報とプロジェクト設定がそのまま使われます。
3. エージェントが提供するモデルと権限のオプションを選択します。利用できるオプションは、インストールされているバージョンによって異なります。

始めるのに必要なエージェントは 1 つだけです。後から、同じワークスペースに他のエージェントのセッションを追加できます。

> エージェントが表示されない場合は、接続中のホストにその CLI がインストールされ、ターミナルで動作することを確認してください。標準以外の場所にインストールした場合は、[実行ファイルのパス](/ja/docs/providers/#実行ファイルのパスを指定する)をご覧のうえ、対応するデーモンを再起動してください。

## 3. 最初のワークスペースを作成する

1. **プロジェクトを追加する**：作業ホスト上の既存のプロジェクトディレクトリを選択します。
2. **ワークスペースを作成する**：まずは既存のディレクトリで始めます。並行して変更を進めるために別々のディレクトリが必要な場合は、[Git worktree](/ja/docs/workspaces/#git-worktree) を使います。
3. **エージェントのセッションを作成する**：用意したエージェントを選び、範囲を明確にしたタスクを送信します。

まずはプロジェクトの把握から始めましょう。次のプロンプトを試してみてください。

> このプロジェクトを読み、何をするものか、主なディレクトリ、ローカルでの実行方法を説明してください。既存のビルドコマンドやテストコマンドも探してください。まだファイルは変更しないでください。

応答とツールの動作が表示されれば、最初のタスクは完了です。次は、文言の修正や README の更新など、小さな変更をエージェントに依頼し、会話内の権限リクエストに応答してみましょう。

変更後は**ファイルと差分**を確認し、**ターミナル**でプロジェクト自身のビルドコマンドやテストコマンドを実行します。詳しくは[ワークスペース](/ja/docs/workspaces/)をご覧ください。

## 4. 別のデバイスで続ける（任意）

### オンラインサービスで接続する

- **デスクトップの作業ホスト**：**オンラインサービス → サインイン / 登録**からサインインし、ホストの同期が有効になっていることを確認します。
- **ヘッドレスホスト**：エージェントを実行するシステムユーザーで、以下のコマンドを実行します。初回認証では、任意の端末のブラウザーでターミナルに表示された URL を開き、確認コードを入力してホストを承認します。

```sh
aitd login
aitd run
```

一度限りの登録用トークンがある場合は、最初のコマンドを以下に替えて標準入力でトークンを渡します。

```sh
aitd login --token-stdin
```

[常時稼働の手順](/ja/docs/daemon/#常時稼働させる)に従い、tmux や systemd でデーモンを実行し続けます。

別のデスクトップ、Android、iOS、または [Ait for Web](https://aitapp.cn/) で**同じアカウントとサービス**にサインインし、オンラインホストの一覧から作業ホストを選びます。ホストとデーモンをオンラインに保ってください。公開ポートの転送は不要で、別のネットワークからも接続できます。

### LAN で直接接続する

- **デスクトップの作業ホスト**：macOS や Linux では、アプリを開くだけでサインインなしにローカル接続できます。LAN 内の別端末から直接接続するには、ローカルホスト設定の **デーモン** で実際の LAN アドレスと固定ポート（例: `7316`）を指定し、デーモンを再起動します。
- **ヘッドレスホスト**：スタンドアロン版の既定の待ち受けは `127.0.0.1:7316` です。サインインせずに起動し、信頼できる LAN のアドレスで待ち受けます。例の IP はホストの実際のアドレスに置き換えてください。

```sh
aitd run --listen 192.168.1.10:7316
```

`<data-dir>/local-api.token` からアクセストークンを読み取るか、起動時に設定した `AIT_SERVER_TOKEN` の値を使います。対象の TCP ポートは信頼できるサブネットにのみ開放します。デスクトップまたはモバイルの **ホストを追加 → 直接接続** で、ホストの IP、ポート、サーバートークンを入力します。Ait for Web はオンラインサービス専用です。

ファイアウォール設定や SSH トンネルは[接続とデータ](/ja/docs/connection/#直接接続)を参照してください。

### モバイルにインストールする

- **iPhone / iPad**：[TestFlight の手順](/ja/docs/platforms/#iphone-と-ipad)に従い、公開招待を承認してインストールします。
- **Android**：[Google Play クローズドテストの手順](/ja/docs/platforms/#google-play-クローズドテスト)に従い、承認済みの Google アカウントでインストールします。
