ワークスペースは、タスクのコンテキストをひとまとめにします。プロジェクトの中で作業を整理し、エージェントとの会話、ディレクトリ内のファイル、ターミナル、Git の変更にアクセスできます。

## プロジェクトとワークスペース

**プロジェクト**は、作業しているコードのディレクトリに対応します。**ワークスペース**は、特定の作業とセッションを整理するものです。エージェントは選択した作業ディレクトリで実行されます。セッションを作成しても、コードの別コピーが自動的に作られることはありません。

まずプロジェクトを追加し、次にそのワークスペースを作成します。既存のディレクトリを使う場合は、正しいコード、設定、プロジェクトの指示が含まれていることを確認してください。

## エージェントにコンテキストを渡す

エージェントを作成するときは、目的とする結果、関連するファイル、検証方法を伝えます。例を示します。

> このプロジェクトにレスポンシブなナビゲーションを追加してください。既存のスタイルに従い、モバイルのレイアウトを確認して、プロジェクトの現在のビルドコマンドを実行してください。

エージェントは、それぞれのネイティブな設定を使用します。プロジェクトの指示、スキル、ツールの読み込み方法は[エージェントのセットアップ](/ja/docs/providers/)をご覧ください。

## 変更を確認して検証する

1. 会話の中で、エージェントの作業を追います。
2. ファイルと差分を開き、変更内容と範囲を確認します。
3. ターミナルで、プロジェクトのビルドコマンドや検証コマンドを実行します。
4. フィードバックを追加するか、次の Git 操作に進みます。

ホームページのデモは、このワークフローを紹介するものです。実際のタスクは実行されず、ファイルも変更されません。

## Git worktree

並行するタスクごとに別々のディレクトリが必要な場合は、プロジェクトの Git worktree のワークフローを使います。worktree を使うと、同じ Git リポジトリに複数の作業ディレクトリを持て、それぞれが独自のブランチとファイルの状態を持ちます。

開始前にリポジトリの状態とターゲットのブランチを確認し、マージする前に変更をレビューしてください。worktree が分離するのはディレクトリとブランチであり、オペレーティングシステムのセキュリティサンドボックスではありません。ワークスペースの作成後も、プロジェクトのセットアップが実行中の場合があります。作業を始める前に、依存関係のインストールと初期化の完了を待ってください。

## コミットとプルリクエスト

ワークスペースの主要なアクションは、実際の Git と PR の状態に応じて、コミット、PR の作成、プッシュ、PR の表示といった操作を提示します。GitHub / GitLab の操作には、作業ホストに Git と、対応する `gh` / `glab` の認証も必要です。

「PR を表示」は既存のリクエストを開くだけで、コミットはプッシュしません。コンフリクト、ブランチの乖離、ブランチが遅れている状態は、先に解消してから進めてください。マージ後、ワークスペースをアーカイブする前に、実行中のエージェントや未回答の承認がないか確認してください。

## スケジュールされたタスク

ワークスペースの新規項目メニューからスケジュールを開きます。実行ごとに、既存のエージェントまたは新しいエージェントを選び、プロンプト、間隔または Cron 式、タイムゾーン、実行回数を設定します。タスクはそのワークスペースに属します。分離されたディレクトリが必要な場合は、先に worktree のワークスペースを作成してください。

タスクは作業ホストのデーモン上で実行されます。クライアントのタブを閉じても、オンラインのデーモンのスケジューラーは停止しません。ホストまたはデーモンがオフラインの間はタスクが実行されず、繰り返しのスケジュールでも、実行できなかった回がすべて再実行されることはありません。一時停止すると以降の自動トリガーは行われなくなりますが、実行中の処理は別途キャンセルする必要があります。

## 別のデバイスで続ける

作業ホストに接続すると、リモートデバイスからそのワークスペースにアクセスできます。ファイルと実行環境はホストに残ります。リモート接続でプロジェクトがスマートフォンにコピーされることはありません。

接続方法とプラットフォームごとの違いは[接続とデータ](/ja/docs/connection/)をご覧ください。
