作業用コンピューターにエージェントをインストールしてサインインし、Ait でセッションを作成するときに選択します。スマートフォンや Web アプリはそのコンピューターに接続するため、各自のエージェント CLI は不要です。Ait にはモデルのサブスクリプションは含まれません。モデル、クォータ、費用は、設定したサービスによって異なります。

プロバイダーの利用可否は、ホストのデーモンとネイティブ CLI のバージョンによって決まります。現在のソースのドキュメントに記載されていても、すべてのストア向けテストビルドに各機能が含まれているとは限りません。

## Codex

Ait はローカルの `codex app-server` を使用します。作業用コンピューターのターミナルで Codex が単独で動作することを確認し、ネイティブのサインインを完了してください。利用できるモデル、推論レベル、権限などの設定は、そのインストールから取得されます。

Codex の指示、スキル、ツール、認証、ネイティブセッションは Codex が管理します。バージョンに依存する機能は、インストールされている CLI に従います。他のエージェントにファイルのリワインド機能があっても、Codex が対応しているとは限りません。

## Claude Code

作業用コンピューターに Claude Code をインストールしたら、サインイン状態を確認します。

```sh
claude --version
claude auth login
claude auth status
```

Ait で **Claude Code** を選択します。別のモードを選ばない限り、ネイティブの `default` 承認モードが使われます。モデルと推論レベルはローカルの CLI から取得されます。ツールの承認と Claude からの質問は、会話の中に表示されます。

Claude Code は認証情報を自身で保持し、`CLAUDE.md`、スキル、MCP を含むユーザー、プロジェクト、ローカルの設定を読み込みます。Ait は画像とテキストの添付、セッションの復旧、ネイティブのチェックポイントへのリワインドに対応しています。ファイルのリワインドは、Claude のチェックポイントで追跡されているファイルのみが対象です。[Claude Code マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/claude-code.md)を参照してください。

## OpenCode

作業用コンピューターで `opencode` をインストールし、設定とサインインを行います。Ait は公式の **`opencode acp`** インターフェイスを通じて接続します。モデル、推論オプション、モードは現在のプロジェクトのネイティブカタログから取得され、そのインストールが提供している場合は Build、Plan、カスタムのプライマリエージェントも含まれます。

テキストの会話、ツールの進行状況、ネイティブの権限リクエスト、キャンセル、復旧に対応しています。ネイティブセッションの一覧表示とインポート、画像入力、質問フォームは、インストールされているバージョンの ACP 機能に依存します。ネイティブのリクエストが選択肢を提供している場合、権限には 1 回のみの承認、継続的な承認、拒否を指定できます。古い CLI では、すべてのオプションが利用できない場合があります。

OpenCode は認証、プロジェクト設定、履歴を管理します。プロジェクトのネイティブな MCP 設定が読み込まれます。Ait はセッションごとに MCP サーバーを動的に挿入せず、OpenCode のネイティブなリワインドも提供しません。カタログの読み込みに失敗した場合は、アプリの診断情報と CLI を確認してから、プロバイダーを更新してください。初回起動時は、ネイティブカタログの初期化に時間がかかることがあります。

プロトコルとバージョンの違いについては、[OpenCode ACP 連携](https://github.com/ait-app/ait/blob/main/docs/decisions/providers/adr-115-opencode-acp-provider.md)を参照してください。

## DeepSeek Harness

作業用コンピューターで `dsh` が実行できるように、DeepSeek Harness をインストールして設定します。Ait はまず CLI を探し、CLI を含む対応済みの DSH デスクトップインストールも検出できます。DSH をインストールまたはアップグレードしたら、Ait デーモンを再起動してください。

既定では、Ait は **web プロファイルのネイティブ対話型ホスト**を使用します。モデルと推論オプションはローカルの設定から取得されます。モードはそのプロファイルのプラグインプリセットから取得され、権限プリセットは別に選択します。会話、添付ファイル、ネイティブ機能で許可された画像、承認、質問、復旧、ネイティブセッションのインポートに対応しています。

デスクトッププロファイルのプラグインは、web プロファイルに自動ではコピーされません。Web ホストを設定済みの別のプロファイルを使うには、デーモンを起動する前に次のように設定します。

```sh
export AIT_SERVER_DEEPSEEK_HARNESS_PROFILE=team-web
```

MCP とプラグインは、対応する DSH プロファイルで管理します。DSH デスクトップアプリがネイティブセッションの書き込みロックを保持している場合は、Ait で続行する前にそちらで解放してください。履歴をインポートしても、アクティブなセッションを引き継ぐことはありません。[DeepSeek Harness マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/deepseek-harness.md)を参照してください。

## Antigravity CLI

Ait は **AGY CLI** を使用します。Antigravity IDE をインストールするだけでは不十分です。CLI をインストールしたら、作業用コンピューターのターミナルで `agy` を実行してネイティブのサインインを完了し、Ait で Antigravity を選択します。

モデルは `agy models` から取得されます。複数ターンのテキスト、テキスト添付、ツールの進行状況、使用量、会話の復旧に対応しています。ローカルの権限は既定で維持されます。ネイティブのヘッドレスインターフェイスには対話的な承認コールバックがないため、質問が必要なツールは拒否される場合があります。作業内容に合わせて AGY のネイティブ権限を設定してください。Ait がグローバルルールを自動的に変更することはありません。

画像入力、実行中のターンへのガイダンス、ネイティブ履歴の完全なインポート、リワインドは連携されていません。インストール、権限、診断については [Antigravity CLI マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/antigravity.md)を参照してください。

## Pi

作業用ホストに Pi をインストールして設定し、`pi --version` と対話型の `pi` が動作することを確認します。Ait は `pi --mode rpc` を使用し、Pi 1.2 以降が必要です。検証済みのベースラインは `@earendil-works/pi-coding-agent` 1.2.0 で、古い 0.x の RPC バージョンとは互換性がありません。

モデルは Pi のカタログから `provider/model` 形式の識別子で取得されます。Ait は、会話、ネイティブモデルが受け付ける画像、ツールの進行状況、キャンセル、セッションの復旧、ネイティブ履歴の検出、インポート、明示的な更新に対応しています。認証、ツール、拡張機能、プロジェクトの信頼、セッションファイルは Pi が管理します。Ait は Pi のモード選択とネイティブなリワインドを提供しません。同じセッションをインポートする前に、他の書き込み元を停止してください。[Pi マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/pi.md)を参照してください。

## Oh My Pi

Oh My Pi（`omp`）と Pi は別のプロバイダーで、インストール、設定、セッションがそれぞれ異なります。作業用ホストにインストールしてサインインし、`omp --version` が動作することを確認してから、Ait で **Oh My Pi** を選択します。現在のドキュメントでは、公式の 18.12.6 RPC v2 を互換性のベースラインとしています。

Ait は ACP ブリッジを公式の `omp --mode rpc-ui` に接続します。動的なモデルと推論オプション、ネイティブの承認と構造化された質問、画像とテキストの添付、サブエージェントの表示、セッションのインポートと復旧に対応しています。ツール、MCP、拡張機能は引き続き OMP が管理します。ネイティブの権限はオペレーティングシステムのサンドボックスではありません。機能と制限事項については [Oh My Pi マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/oh-my-pi.md)を参照してください。

## MiniMax Code

Ait は、`mmx` マルチメディア/API CLI ではなく、MiniMax Code の `mcode acp` を使用します。[MiniMax Code マニュアル](https://github.com/ait-app/ait/blob/main/docs/operations/minimax-code.md)に従って、対応する Node.js バージョンを用意し、ネイティブ CLI をインストールして、`mcode login` を実行してください。`mcode --version` を確認し、デーモンを再起動して、プロバイダーのカタログを更新します。

**MiniMax Code** を選択すると、サインイン済みのネイティブプログラムのモデル、思考レベル、作業モード、権限を利用できます。Ait はテキストと画像、ストリーミング応答、ツールの進行状況、承認、停止、Ait セッションの復旧に対応しています。外部セッションのインポート、リワインド、リアルタイム音声は利用できません。マニュアルには 0.7.1 での検証が記録されています。カタログで実際に利用できるモデルを選択し、カタログが変わった場合は更新して選び直してください。

## 実行ファイルのパスを指定する

デスクトッププロセスが CLI を見つけられない場合や、標準以外の場所にインストールしている場合は、デーモンまたは開発用エントリを起動する前に、該当する変数を設定します。必要な変数だけを設定し、各例は実際の実行ファイルのパスに置き換えてください。

```sh
export AIT_SERVER_CODEX_BIN=/absolute/path/to/codex
export AIT_SERVER_CLAUDE_BIN=/absolute/path/to/claude
export AIT_SERVER_OPENCODE_BIN=/absolute/path/to/opencode
export AIT_SERVER_DEEPSEEK_HARNESS_BIN=/absolute/path/to/dsh
export AIT_SERVER_ANTIGRAVITY_BIN=/absolute/path/to/agy
export AIT_SERVER_PI_BIN=/absolute/path/to/pi
export AIT_SERVER_OMP_BIN=/absolute/path/to/omp
export AIT_SERVER_MINIMAX_CODE_BIN=/absolute/path/to/mcode
```

これらの変数はプログラムを指定するもので、モデルサービスの認証情報は保存しません。変更後は、対応するデーモンを再起動してください。ブラウザーやスマートフォンの画面を開き直しても、作業ホストの環境は変わりません。

## プロバイダーを選ぶ

セッションを作成または再開する前に、作業ホストから返されるモデル、モード、権限を確認してください。各プロバイダーの機能は、ネイティブプログラムと Ait のアダプターの両方に依存します。権限モードは、オペレーティングシステムレベルの分離を提供するものではありません。

次は[ワークスペース](/ja/docs/workspaces/)に進んでください。利用可否、サインイン、クォータに関する問題は、[トラブルシューティングとサポート](/ja/docs/support/)を参照してください。
